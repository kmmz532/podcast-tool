# 要件定義書

## 1. 概要
PWA対応、オフライン対応のPodcastプレイヤーWebアプリを開発する。
サーバーを持たない完全クライアントサイドのアプリとし、データはすべて端末内に保存する。

### 1.1 前提、方針
- クライアントのみ: バックエンドは持たない。静的ホスティング（ここではGitHub Pages）で配信する
- データは端末のみ: アカウント、端末間同期はなしとする。端末移行はOPMLのインポート/エクスポートで実行する
- 対象環境: スマホ、PCの両方。PevenMUIのモバイル/デスクトップ両レイアウトを利用する

### 1.2 対象ブラウザ
| 環境 | ブラウザ | 備考 |
|---|---|---|
| PC | Chrome / Edge / Firefox 最新版 | |
| Android | Chrome 最新版 | ホーム画面に追加して利用する想定 |
| iOS / iPadOS | Safari 16.4以降 | ホーム画面に追加して利用する想定。制約は §5 を参照 |

## 2. 用語
| 用語 | 意味 |
|---|---|
| 番組 (Podcast) | 1つのRSSフィードに対応する番組 |
| エピソード | 番組内の1回分の配信。音声ファイル1つを持つ |
| 購読 | 番組をアプリに登録し、更新を追う状態 |
| ダウンロード | エピソードの音声ファイルを端末に保存し、オフラインで再生できるようにすること |

## 3. 機能要件

### 3.1 MVP

#### F-1 番組管理
| ID | 要件 |
|---|---|
| F-1-1 | RSSフィードのURLを入力して番組を購読できる |
| F-1-2 | 購読中の番組を一覧表示できる（アートワーク、タイトル、未再生数） |
| F-1-3 | 番組の購読を解除できる（ダウンロード済みファイルも削除する） |
| F-1-4 | 番組のエピソード一覧を新しい順に表示できる |
| F-1-5 | 手動で番組を更新（フィード再取得）できる。全番組一括更新もできる |
| F-1-6 | アプリ起動時に、前回の更新から一定時間（既定6時間）経っていれば自動で更新する |
| F-1-7 | フィードを直接取得できない場合（CORS）、設定したプロキシ経由で取得できる（§5.1） |

#### F-2 再生
| ID | 要件 |
|---|---|
| F-2-1 | エピソードを再生、一時停止できる |
| F-2-2 | シークバーで再生位置を変更できる。前後スキップ（既定: 戻る15秒 / 進む30秒）ができる |
| F-2-3 | 再生速度を変更できる（0.5〜3.0倍、0.1刻み） |
| F-2-4 | 再生位置を自動保存し、次回同じエピソードを開いたときに続きから再生する |
| F-2-5 | 終了まで再生したエピソードを「再生済み」にする。手動で再生済み/未再生を切り替えられる |
| F-2-6 | 画面遷移しても再生を続け、ミニプレイヤーを常に表示する。タップでフルプレイヤーを開く |
| F-2-7 | OSのロック画面、通知領域、キーボードのメディアキーから操作できる（Media Session API） |
| F-2-8 | 再生キュー（次に再生）にエピソードを追加、並べ替え、削除できる。再生が終わったら次を自動再生する |
| F-2-9 | エピソードの説明（ショーノート）を表示できる。リンクは別タブで開く |

#### F-3 データ管理
| ID | 要件 |
|---|---|
| F-3-1 | 購読リストをOPMLでエクスポートできる |
| F-3-2 | OPMLファイルをインポートして一括購読できる |

#### F-4 設定
| ID | 要件 |
|---|---|
| F-4-1 | 言語（日本語/英語）、テーマ（ライト/ダーク/システム）を変更できる |
| F-4-2 | スキップ秒数、既定の再生速度を変更できる |
| F-4-3 | プロキシを複数登録し、試す順番を設定できる（未登録なら直接取得のみ） |

### 3.2 付加機能

#### F-5 音声ファイルキャッシュ（ダウンロード）
| ID | 要件 |
|---|---|
| F-5-1 | エピソードを手動でダウンロードできる。進捗を表示し、キャンセルできる |
| F-5-2 | ダウンロード済みのエピソードはオフラインで再生、シークできる |
| F-5-3 | ダウンロード済みエピソードを一覧表示し、個別、一括で削除できる |
| F-5-4 | 使用容量と、ブラウザが許す残り容量を表示する |
| F-5-5 | 再生済みになったダウンロードを自動削除する設定を持つ（既定OFF） |
| F-5-6 | 番組ごとに「新着を自動ダウンロード」を設定できる（Wi-Fi判定はできないため既定OFF） |
| F-5-7 | CORSで取得できずダウンロードできなかったエピソードは「ダウンロード不可」と表示する。再生（ストリーミング）はできる |
| F-5-8 | プロキシを追加、変更したら、「ダウンロード不可」のエピソードをまとめて再試行できる |

#### F-6 自前プロキシ
CORSで取得できないフィード、音声のための、自分で用意するプロキシ。アプリ本体とは別にデプロイする。
| ID | 要件 |
|---|---|
| F-6-1 | Cloudflare Workers で動く自前プロキシを用意する（同じリポジトリの別ディレクトリ） |
| F-6-2 | Range要求を転送し、音声をストリームのまま返す（全体をメモリに載せない） |
| F-6-3 | 許可したアプリのOriginからのリクエストだけを受け付ける。必要ならアクセストークンを確認する |
| F-6-4 | アプリ側は、設定にプロキシを1件追加するだけで使える（アプリのコード変更は不要） |

#### 将来の候補（今回の範囲外）
- 番組の検索（iTunes Search API / Podcast Index。CORSやAPIキーの都合で要調査）
- Apple Podcasts等の共有URLからの登録
- チャプター表示（Podcasting 2.0 `podcast:chapters`）、文字起こし表示
- スリープタイマー
- 無音カット、音量正規化（Wasm導入候補）

## 4. 非機能要件
| ID | 区分 | 要件 |
|---|---|---|
| N-1 | オフライン | 一度読み込めば、オフラインでもアプリが起動し、購読リスト、エピソード一覧、ダウンロード済みエピソードを使える |
| N-2 | PWA | ホーム画面に追加でき、スタンドアロン表示で起動する。新バージョンがあれば更新を案内する |
| N-3 | 性能 | 購読100番組、合計1万エピソードでも一覧がもたつかない（仮想スクロール） |
| N-4 | 永続化 | ストレージの永続化（`navigator.storage.persist()`）を要求し、ブラウザに勝手に消されにくくする |
| N-5 | 多言語 | 日本語、英語に対応する |
| N-6 | アクセシビリティ | キーボードだけで主要操作（再生/停止、スキップ、移動）ができる |
| N-7 | プライバシー | 外部へ送信するのはフィード、音声の取得リクエストと、設定したプロキシへのリクエストのみ。解析ツールは入れない |

## 5. 制約、リスク

### 5.1 CORS
- 多くのPodcastフィードはCORSヘッダーを返さないため、ブラウザから直接 `fetch` できない
- 対応: まず直接取得し、失敗したら設定したプロキシ経由で再試行する。プロキシ未設定ならエラー表示で設定を案内する
- 公開CORSプロキシは可用性、プライバシーの保証がないため、既定値は空にしてユーザーに選ばせる
- 音声ファイルの再生は `<audio>` 要素で行うためCORSの影響を受けない。ダウンロードはCORSの影響を受ける（設計書 §8.3）
- MVPでは、取得できない番組、エピソードがあることを許容する。根本的な対策は付加機能の自前プロキシ（F-6）で行う。通信経路は後から足せる設計にする（設計書 §5）

### 5.2 iOS Safari
- ホーム画面に追加していない状態では、7日間利用しないとストレージが消される可能性がある
- バックグラウンド再生、ロック画面操作はホーム画面追加時のほうが安定する。実機で確認が必要

### 5.3 ストレージ容量
- ブラウザごとに上限が異なる（端末空き容量の一定割合）。容量不足ならダウンロードを失敗させて通知する
